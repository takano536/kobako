# kobako

自分のサーバーで動かす、日本語の家計簿です。

収入と支出を記録し、月ごとの収支やカテゴリ別の支出を確認できます。  
まだ開発中ですが、基本的な記録と振り返りには使える状態です。

## できること

- 収入・支出の登録、編集、削除
- 月ごとの収入、支出、収支の確認
- カテゴリ別支出の集計
- 月、種別、カテゴリによる取引の絞り込み
- パソコンとスマートフォンに対応した日本語 UI
- 「らくな家計簿」の Excel エクスポートファイルからのインポート

## 現在の制限

現在は 1 つの家計を管理する構成です。ユーザー認証や家計の切り替えにはまだ対応していません。

- Android版の日本語 Excel 形式のみ対応
- 振替はインポートと一覧表示のみで、編集・削除は未対応
- 手入力の取引では口座を指定できない
- 口座管理・残高画面は未実装

認証がないため、インターネットへ直接公開せず、ローカルネットワークや VPN 内で使ってください。

## 「らくな家計簿」からのインポート

Realbyte「らくな家計簿」（Android 日本語版）の Excel エクスポートファイル（`.xlsx`）を kobako に取り込めます。

### 使い方

取引画面の「取り込む」リンクから `/transactions/import` を開き、ファイルを選択します。内容をプレビューして確認した後、画面に選択されたままの同じファイルをもう一度送信すると確定します。JavaScript が無効でも同じフォームを二回送信して確定できます。取り込み完了後の一覧リンクは、取り込んだ期間の最新月を開きます。プレビューではデータベースを変更せず、ファイル本体も保存しません。

### 対応形式と制限

- **対応アプリ：** Realbyte「らくな家計簿」Android 日本語版のみ（iOS・PC Manager・CSV・`.xls`・`.mmbak` は対象外）
- **ファイル形式：** `.xlsx`（本体の上限 5 MiB）
- **最大行数：** 10,000 行（ワークシートの読み込み中に制限）
- **列の順序：** 日付、資産、分類、小分類、内容、JPY、収入/支出、メモ、金額、通貨、資産の 11 列
- **検証：** 行をすべて検証し、エラーが一つでもあればファイル全体を確定しません
- **金額と通貨：** 金額は整数または `.0` で終わる値、通貨は JPY だけを受け付けます。金額・日付シリアルの数値表記は 64 文字までです

### 取り込む項目・しない項目

**取り込む：**

- **日付：** 取引日として保存します
- **資産：** household 内の口座として保存し、同名は再利用、未登録名は確定時に一度だけ作成します
- **分類 / 小分類：** 通常行では「分類」または「分類 / 小分類」というカテゴリ名にまとめます。同じ種別で同じ名前のカテゴリは再利用し、なければ作成します
- **内容 + メモ：** 前後の空白を除き、同じ値を一度だけ残してメモ欄に `/` で結合します
- **JPY 金額：** 通常行は符号付き、振替は正の整数として保存します
- **収入/支出：** 通常行の取引種別として保存します
- **引き出し：** 振替元 B「資産」、振替先 C「分類」、金額 F の一つの振替として保存します

**取り込まない：**

- **I/J/K 列（追加金額、通貨値、追加資産値）：** J で JPY を確認しますが、J は保存しません。保存する金額は F のみで、I/K も保存せず、手数料も推測しません

### 振替（資産間の移動）への対応

振替は収入や支出の組には変換せず、`transfers` の一件として保存します。振替元の残高を減らし、振替先を増やしますが、収入・支出・カテゴリ別・月次収支には含めません。

空の資産名、同じ資産への振替、不正な金額・日付、未知の種別は行エラーです。未知だが空でない資産名は新しい口座としてプレビューに表示されます。

### 重複の防止

同じファイル（内容の SHA-256 ハッシュが一致するもの）を再度取り込もうとすると、前回の取り込み日時を示す「すでに取り込み済み」として検出し、新しい取引・振替・口座・カテゴリは登録しません。
SHA-256 は 64 文字の小文字 16 進数として DB でも検証します。

## Docker Compose で起動する

Docker Engine と Docker Compose v2 が必要です。

```sh
git clone https://github.com/takano536/kobako.git
cd kobako
cp .env.example .env
docker compose up --build
```

起動したら、ブラウザで <http://127.0.0.1:3000> を開きます。

データは Docker volume に保存されます。通常の停止には次のコマンドを使います。

```sh
docker compose down
```

`docker compose down -v` を実行するとデータベースも削除されるため注意してください。

## ローカル開発

必要なもの：

- Node.js 24.21.0
- Corepack
- PostgreSQL 17 以上

```sh
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env
pnpm db:migrate
pnpm dev
```

開発サーバーは <http://localhost:3000> で起動します。

## テスト

```sh
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test:unit
pnpm test:integration
pnpm build
pnpm test:e2e
```

integration test と E2E には、開発用とは別のテスト専用データベースが必要です。接続先は `.env.example` を参考に設定してください。

## 構成

kobako は pnpm workspace を使ったモノリポです。

- `apps/web`：Next.js による Web アプリ
- `apps/worker`：バックグラウンド処理用のプロセス
- `packages/db`：PostgreSQL、Drizzle ORM、migration、入力検証
- `compose.yaml`：ローカル実行用の Docker Compose 構成
