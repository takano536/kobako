# UI レイアウト規則

## 画面の順序

月単位で表示する概要・取引画面は、次の順序を共通にします。

1. グローバルヘッダー
2. `PageHeader`（ページの `h1`、必要なら件数）
3. `MonthSwitcher`
4. 画面固有の操作（取引画面では `FilterBar` の絞り込みチップ行）
5. 本文

`MonthSwitcher` は月移動のリンクと月選択のボタンを持つ `nav` です。左右の矢印は 44px の操作領域に 12px のシェブロン（`PageHeader` の戻りリンクと同じ線画）を中央揃えで置き、月表示は 5rem 以上の列に中央揃えし、全体を内容幅（168px 前後）にまとめます。矢印の操作領域は 44px あるため行の左端を内側の余白ぶん（16px）外へ出し、左のシェブロンの線が本文の左端に揃うようにします（ページ見出しの戻りリンクと同じ扱い）。月表示をタップするとアプリ内の月グリッドが開き、選んだ月へ現在の絞り込み条件を保ったまま移動します。取引一覧を資産で絞り込んでいるときだけ、月グリッドの先頭に「全期間」を出します。全期間の表示は同じ高さ・余白のまま、矢印の代わりに「全期間」と絞り込みリンクを並べます。取引では `month`・`type`・`category`・`account`・`origin` を次月・前月の URL に引き継ぎます。

取引画面の絞り込みは、月スイッチャーの直下に常時表示するチップ1行です。並びは「種別」「カテゴリ」「資産」「APIのみ」で、条件があるときだけ右端に「条件をクリア」を置き、4条件をすべて外します（0件でも押せます）。未選択のチップはラベルと chevron だけ、選択中は淡い緑の地に値と `×`（その条件だけを外す）を添えます。チップ行は下罫線を置かず、下余白は `--space-item`（8px）です。値はチップ直下のメニュー（`role="menu"`、項目は `menuitemradio`）で選び、選んだ時点で URL を置き換えます（履歴を増やさず、スクロールも保ちます）。絞り込みの変更（選択・`×`・「条件をクリア」・空の一覧の「条件をクリア」）は `FilterTransition`（`filter-transition.tsx`）の静かな遷移で行い、骨組みは出しません。チップは押した時点で選択状態になり（`useOptimistic`）、一覧は応答が届くまで直前の内容を残して `aria-busy` を付け、少し薄くします（位置と高さは変えません。速い応答でちらつかないよう 120ms 遅らせます）。応答が届くと一覧と件数だけが差し替わり、本文のフェードも行いません（`html[data-filter-transition]`）。遷移が終わるとチップはサーバーの値に戻るため、失敗しても URL と食い違いません。メニューの高さは `min(60vh, 24rem)` と画面に残る高さ（狭い画面では固定の下部ナビゲーションの上端まで）に抑えて中でスクロールし、下に入りきらず上の方が広いときはチップの上に開きます。カテゴリのメニューは種別で絞り、「支出」「収入」の見出しでまとめます。資産のメニューは右端に資産カテゴリ名を小さく出します（名前と同じなら出しません）。「APIのみ」はメニューを持たないトグル（`aria-pressed`）です。種別が振替のときカテゴリのチップは無効にします。チップは高さ 36px で、幅が足りなければ折り返し、横スクロールを出しません。

グローバルナビゲーションは、概要・取引・残高の三つのリンクだけを持ちます。月表示のある画面からのリンクは有効な `month` を引き継ぎ、設定への導線はヘッダー右端の歯車（`aria-label="設定"`、`title="設定"`）だけにします。ナビゲーションには取引登録の `＋` を置かず、概要・取引・固定費・残高の登録操作は画面右下の `RegisterFab` に限定します。空状態には同じ登録先の補助リンクを置きます。

幅が `30rem` 以下では、ヘッダーにブランドと設定歯車だけを置き、三つのリンクを画面下端に固定します。下部ナビゲーションは紙面色・上罫線・44px 以上の操作領域を使い、各リンクは線画アイコンと短いラベルを縦に並べます。選択中はアクセント色、未選択はミュート色とし、選択中の背景装飾は付けません。幅が `30rem` を超える場合は、ブランドの隣に文字リンクを置き、設定歯車を右端に寄せます。現在の画面には `aria-current="page"` を付け、デスクトップではアクセント色の細い下線で示します。下部ナビゲーション分の下余白と safe-area を本文に確保し、入力フォーカス中は下部ナビゲーションを隠します。高さが `32rem` 以下の狭いビューポートでは、ナビゲーションを本文の後ろを覆わない通常フローへ切り替え、ブランドと設定歯車を一行、アイコンを省いた 44px の文字リンクを二行目に置きます。

セクションの対応は、`/` が概要、`/transactions/**` が取引、`/balances/**` が残高、`/settings/**` が設定歯車です。`/accounts/new` は残高に対応し、`/accounts/[id]/edit` は検証済み `return` のセクション（取引・残高・概要・設定）を引き継ぎ、不正または未指定なら取引を選びます。

取引一覧は現在の期間と絞り込み条件に一致する行をすべて表示します。旧 URL の `page` パラメータは無視します。
通常取引の行はカテゴリと、紐づく資産の名前を表示します。資産未指定の取引では資産名を表示しません。振替の行は送金元・送金先を表示します。

取引一覧の `account` による資産の絞り込みは、通常取引の `account_id` と振替の送金元・送金先を一つの資産として扱います。削除済み資産も過去の取引を確認するため絞り込み対象にできます。新規入力の候補には削除されていない資産（`status` が `closed` の資産を含む）を表示し、編集で既に参照している削除済み資産は保持します。

残高画面は月切替を持たず、次の順序にします。

1. グローバルヘッダー
2. `PageHeader`（ページの `h1`）
3. 集計（純資産を主、資産・負債を副）
4. 資産カテゴリ（`kind`）順にまとめた残高一覧

残高一覧は空の資産カテゴリを表示せず、保存された資産カテゴリを現金・銀行・クレジットカード・デビットカード・電子マネー・その他の順で表示します。各資産カテゴリの見出し行に名前と列ラベルを置き、資産行は名前を左、金額領域を右に揃えます。名前は折り返し、通常幅では金額を右揃えで一行に保ちますが、狭幅・拡大時は金額の符号・通貨・全桁を保ったまま列を再配置して折り返します。銀行は「支払予定」「残高」、クレジットカードは「決済予定」「未決済」を見出し行に表示します。クレジットカードの決済予定列は請求確定（`billed-unpaid`／`overdue`）かつ未払いの全請求期間の残額を表示し、未決済列には現在の請求期間の締め前（`unbilled`）残額だけを表示します。設定なし・設定不備のカードは両列とも不明表示にします。支払日の表示は行いません。モバイルでも名前と金額領域を同じ行に置き、名前と金額を行の中央に揃えます。
集計は全期間を対象とし、未来日付の取引を含みます。初期残高は反映せず、資産未指定の取引は除外します。資産ごとの計算上の残高は `income - expense - transfersOut + transfersIn` です。0円の「その他」は資産カテゴリラベルを付けず、計算は BigInt/整数文字列で行います。集計は `PageSummary` に統一し、見出し（「残高の集計」など）を置かずに領域の名前だけを `aria-label` で残します。主役の数字を1つだけ大きく出し（固定費は月あたり、残高は純資産）、残りは右端に寄せて小さく並べます。副数字の右端は一覧の金額列の右端に揃えます。金額の色は「金額の色」の規則に従い、固定費の支出と負債は赤、資産と黒字の純資産は青、0円はインク色です。30rem 以下では折り返し、主役の下に副数字を右寄せで置きます。

## 資産の導線と設定

資産一覧の専用ページやグローバルナビゲーション項目は持ちません。残高画面から「資産を登録」で登録し、設定画面の「資産」セクションに有効な資産を一覧表示します。各行は「カテゴリ管理」の行と同じ1行の高さで、資産名を左（長い名前は省略）、資産カテゴリ名を矢印の手前に小さく置きます（名前と同じなら出しません）。各行から `/accounts/[id]/edit?return=%2Fsettings` の既存モーダルを開き、保存後は設定画面へ戻ります。

資産設定フォームは名前・資産カテゴリ・カードの現在条件を一つにまとめます。カード条件は現在値だけを編集し、過去の条件を表示・編集する独立画面はありません。資産の削除確認は `deleted_at` を設定する論理削除だけを実行し、取引・振替・カード条件の参照を残します。保存時点で論理削除済みの資産は変更せず、保存拒否を表示します。

## 設定画面

設定は一覧（`/settings`）と、カテゴリごと・データ削除ごとの独立ページで構成します。

- 一覧: 「外観」「カテゴリ管理」「データ管理」の三つのセクションを `h2` で分けます。カテゴリ管理・データ管理の各行は 44px の行全体リンクにします。行の文字は見出しの左端に揃え、下線は付けず、右端に矢印を置きます。ホバー・キーボードフォーカスは背景色で示し、フォーカスリングは行の外側に出します。危険な「すべてのデータを削除」は独立したセクションに置き、文字だけを危険色にして罫線は他と同じ中立色にします。
- 外観: 「ライト」「ダーク」「システムに合わせる」の 3 枚のカードを `radiogroup`／`radio`（`aria-checked`）で並べ、補助文は「システムに合わせる」の「端末の設定に従います」だけにします。各カードは実際のテーマトークン（`data-theme` で範囲を限定）で描いた面・文字・罫線・アクセントの小さなプレビュー（`aria-hidden`）とラベルを持ち、システムは左右にライト・ダークを並べます。選択中は境界線を太くし、ラジオの丸に点を付けて、色だけに頼りません。矢印キー・Home/End はフォーカスだけを移し、Enter／Space（クリック）で確定し、確定した時点で保存ボタンなしに適用します。カードは 11rem 以上の列で折り返し、`30rem` 以下ではプレビューを左、ラベルを右に置いた 1 列にします。サーバー描画では選択が不明なので、すべて未選択で描画し、ハイドレーション後に選択を表示します。
- 支出・収入カテゴリ: `h1` だけを見出しにし、件数は `PageHeader` の件数（取引と同じ表示）に置きます。各行はカテゴリ名を文字で左、「名前を変更」「上へ」「下へ」「削除」を右に並べます（44px の文字ボタン、モバイル 390px でも一行を基本とし、名前は折り返します）。「名前を変更」でその行がインライン編集（入力・「保存」・「キャンセル」）に切り替わり、フォーカスは入力へ移ります。Escape または「キャンセル」で元に戻り、フォーカスは「名前を変更」へ戻ります。サーバーエラーでは編集を開いたまま入力値を保持し、`aria-invalid` と `aria-describedby` で行の下のエラーに関連付けます。使用中カテゴリの削除拒否も同じ行の下に表示します。端の「上へ」「下へ」は無効状態にし、追加フォーム（ラベル「新しいカテゴリ」）は一覧の末尾に置きます。
- 資産カテゴリ: 固定分類の一覧だけを置き、見出しを重ねず「固定の分類です。追加・削除・名前変更はできません。」の一文を添えます。
- すべてのデータを削除: 警告「この操作は取り消せません。」と確認欄のエラーは本文サイズにし、警告は危険色と太さで強調します。エラーは確認欄の直下に置き、`aria-describedby`・`aria-invalid` で関連付けます。モバイルでは見出し内の設定への戻りリンクも、本文と干渉しないように折り返します。

画面確認用のスクリーンショットは `docs/screenshots/settings/<画面>-{desktop,mobile}.png` に置きます。

## 固定費画面

`/fixed-costs` は固定費の集計（月あたりを主、年間を副）、チップ式の絞り込み、グループ切替、固定費一覧の順に表示します。集計に見出しは置きません。絞り込みはカテゴリ・頻度・資産を値付きチップで操作し、条件がある場合は「条件をクリア」を表示します。グループ設定は `kobako-fixed-cost-group` に保存します。

固定費の一覧は残高一覧と同じく行全体を編集画面へのリンクにし、金額を右揃え、支払頻度・日付・資産をメタ情報として表示します。固定費がない場合は登録導線を、条件に一致しない場合は条件解除の空状態を表示します。30rem 以下では集計を折り返し、横スクロールを発生させません。

## 子画面の戻り先

一覧や設定から開く子画面の戻り先は、ブラウザ履歴ではなく明示した内部 URL で決めます。`PageHeader` の `backLink` を使い、左向きの細いシェブロンとページ見出しを一つのリンクとして置きます。シェブロンは装飾（`aria-hidden`）とし、ページの `titleAriaLabel` がある場合は「現在の見出し — 戻り先」をリンクの accessible name にします。リンクは下線を付けず、既存の 44px 以上の操作領域と `:focus-visible` のフォーカス表示を保ちます。

トップレベルの概要・取引・残高・設定には戻りリンクを置きません。子画面では現在の導線が渡した有効な月や絞り込み条件を戻り先に残し、資産設定の `return` は取引一覧のパス・資産 ID・月・種別・カテゴリを検証してから再構築します。不正な月や外部 URL は採用せず、固定の安全な一覧 URL にフォールバックします。保存・登録・削除後のリダイレクト、キャンセル、未保存状態の扱いは見出しリンクの変更で変えません。

## 共通コンポーネントとアクション

共通部品は `apps/web/app/_components/` に置き、各ページから直接 import します。

- `PageShell`: `layout.module.css`／`page-transition.tsx`、`PageHeader`: `page-header.tsx`／`page-header.module.css`、`SectionHeading`: `ui.tsx`／`ui.module.css`、`MonthSwitcher`: `ui.tsx`／`month-switcher.module.css` でページの骨格を提供します。`PageTransition` は React 19 の `ViewTransition` を使い、ヘッダー・ナビゲーションを含まない本文だけを切り替えます。
- `PageSummary`: `page-summary.tsx`／`page-summary.module.css`。固定費・残高の集計を同じ組み方で表示する共通部品です。見出しは置かず `aria-label` だけを残し、`primary`（主役の数字）と `secondary`（右端に寄せる副数字）を受け取ります。金額は `SignedYen` を渡し、色は金額の色の規則に任せます。
- `FormActions`: `form-actions.tsx`／`form-actions.module.css`。フォームの送信行を一つにまとめ、`showCancel` を渡した画面だけ左にキャンセル（`variant="secondary"`）を置き、右端に送信を並べます。キャンセルは `router.back()` で開いた元の画面へ戻ります。カードで開く登録フォーム（取引・資産・固定費）はキャンセルを持ち、同じ URL を直接開いたページと編集フォームは持ちません（編集は見出しの戻るで閉じます）。
- `Button`／`LinkButton`、`Card`、`Field`／`Input`／`Select`、`Amount`、`Section`: それぞれ `button.tsx`／`button.module.css`、`card.tsx`／`card.module.css`、`field.tsx`／`field.module.css`、`amount.tsx`／`amount.module.css`、`section.tsx`／`section.module.css` に置きます。
- `CategoryBreakdown` は `overview/category-breakdown.tsx`／`category-breakdown.module.css`、残高・取引行・フォーム・設定・取込は各ページ／部品の専用 Module に置き、レスポンシブ規則も同じ所有 Module に co-locate します。
- `RegisterFab` と `ActionLink`: ナビゲーション用リンクと登録導線の共通部品です。概要・取引・固定費・残高の登録導線は `RegisterFab` とし、`<a>` の `aria-label` に「取引を登録」「固定費を登録」「資産を登録」を設定します。FAB は 56px の円形で固定配置し、デスクトップでは一覧の金額列右端に揃え、モバイルでは下部ナビゲーションの上に置きます。`RegisterTransactionAction` は空状態の補助導線として使い、`ActionLink` はその他の画面内リンクに使います。

見出しはページ見出しと、カード・ダイアログおよびセクションの見出しで体系を分けます。

| 種別                                         | サイズ                                      | 太さ | 行間 | 字間    |
| -------------------------------------------- | ------------------------------------------- | ---- | ---- | ------- |
| ページ見出し                                 | `--text-title`（23px、`30rem` 以下は 21px） | 500  | 1.15 | -0.03em |
| カード・ダイアログの見出しとセクション見出し | `--text-heading`（15px）                    | 500  | 1.3  | -0.02em |

- `LinkButton` の塗りつぶしボタンは `--text-small`、`padding: 0.5rem 0.8rem`、`min-height: 2.25rem`（36px）です。フォーム送信の `.button` は 44px（`padding: 0.55rem 0.9rem`）を保ちます。
- `EmptyState`: ページ用（`page`）とセクション用（`section`）の密度を使い分けます。
- `FilterBar`: 取引画面の絞り込みチップ行（`filter-chips.tsx`）に、メニュー項目だけを渡すサーバー側の入口です。
- カード・ダイアログ（`OverlayCard`、取込の確認ダイアログ）の表示中は `useBackgroundScrollLock`（`use-background-scroll-lock.ts`）で背景スクロールを止め、閉じたら元に戻します（スクロール位置と横幅は変えません）。
- 本文ページ間の遷移は `NavigationShellProvider`（`navigation-shell.tsx`）が扱います。クリックの直後は `NavigationShell` が遷移先の骨組みを本文の位置に表示し、現在の本文は state を保ったまま隠します。Next.js の遷移が確定した commit で骨組みを外し、本文へ差し替えます。骨組みは画面ごとに `page-skeletons.tsx` で定義した `PageSkeleton`（`page-skeleton.tsx`／`page-skeleton.module.css`）で、遷移先と同じ `PageShell` の幅・ヘッダー・月切替・セクション見出しを使い、固定の文言はそのまま表示します。データ次第の件数・金額・行だけを面に置き換えます。骨組みを出している間は本文の View Transition を止め（`html[data-nav-frame]`）、確定した本文がその場で入るようにして、fade による白抜けを作りません。タップしたタブへは直ちに `aria-current` を移し、取得中は `aria-busy` を付けます。
- `router.push` は同時に1件だけ実行し、連打は待機先を最後のタップで上書きします。開いている画面のタブをもう一度押しても取得しません（`router.push` を呼ばず、先頭へ戻すだけです）。取得中の画面のタブを押した場合は、確定した後に元の画面へ戻る遷移を1件だけキューに入れます。実行中の遷移が確定したら、最後の遷移先が違う場合だけ次を実行します。履歴移動・月や条件の変更・カードを開く操作などに移ったら待機先を破棄します。取得中の画面のタブを押して戻る場合も骨組みは出しません（表示中の本文を一瞬消すだけになるため）。修飾キー、`target`、`replace` は通常のリンクの動作を保ちます。
- 同じ画面の月の切り替えも同じキューで扱います。押した直後に遷移先の骨組みを出し、骨組みの月切替には切り替え先の月を表示します。骨組みの月切替だけは押せる状態にし、連打では表示中の月が1タップごとに進み、取得は待機中の1件にまとまります。最後の月が確定するまで骨組みを保ち、途中の応答で別の月の本文を一瞬出しません。月の切り替えはスクロール位置を保つため、骨組みは置き換えた本文の高さ（`min-height`）を保ちます。カードの枠・背景静止は変更しません。
- 一時的な RSC GET の503は `rsc-navigation-retry.ts` で150ms・450ms後に最大2回だけ取り直してから Next.js に渡します。Next.js は503を直接渡すと文書ナビゲーションへ切り替えるためです。先読み・POST/Server Action・通常の文書取得は取り直しません。全試行が失敗すれば従来の文書ナビゲーションへフォールバックします。Workers の1102そのものや、200応答の途中で切れたRSCストリームを修復する処理ではありません。
- ページ（`@modal` 以外）には `loading.tsx` を置きません。`loading.tsx` は文書の読み込みもストリーミングに変え、本文が JavaScript で差し込まれるまで隠れたまま（JavaScript が無いと骨組みのまま）になり、ストリーミング後の `notFound()` も 404 ではなく 200 になるためです。文書の読み込みは本文までサーバーで描画します。
- カードを開くリンク（取引行・振替行・資産の編集）は、カードの枠と見出しを各モーダルの `layout.tsx`、骨組みを `loading.tsx` の `CardSkeleton` が担当し、本文の取得を待たずに枠と骨組みを先に表示します。本文が遅れて届く場合、デスクトップでは `OverlayCard` は入力欄が現れた時点でフォーカスします。
- `OverlayCard` の初期フォーカスは、主たる入力手段で分けます（初回マウント時に `matchMedia('(pointer: coarse)')` で1回判定）。デスクトップ（`pointer: fine`）は `autoFocusSelector` の入力欄（取引は金額欄、資産は名前欄）へフォーカスします。タッチ端末はソフトキーボードを勝手に開かないよう入力欄へフォーカスせず、カード（`#entry-dialog`、`role="dialog"`・`tabIndex={-1}`）自体へフォーカスし、ストリーミングで後から届く入力欄も待ちません。カード自体のフォーカスリングは出さず、Tab は先頭の戻るボタンへ移り、Shift+Tab でもカードの外へ出ません。送信エラー時の金額欄など、利用者の操作に続くフォーカス移動は端末で分けません。
- カード（`OverlayCard`・取り込み確認）の見出し行は、`PageHeader` の戻りリンクと同じく chevron と見出し文字の両方で戻ります。chevron の `button` と見出し（`h1`/`h2`）を兄弟のまま内容幅のラッパーに入れ、`button::after` をラッパー全体へ広げて当たり判定にします。見出しの右側の空白は含めず、見出しが折り返しても全体を覆います。戻るボタンの名前は「＜見出し＞ — 戻る」、ダイアログの `aria-labelledby` は素の見出しを指します。
- カードの骨組みは `skeleton.module.css` の面を使い、`--soft-control` を1.4sで明滅させ、`prefers-reduced-motion: reduce` では明滅させません。`role="status"` と視覚非表示のラベルで1回だけ読み上げ、面そのものは `aria-hidden` にしてフォーカスを奪いません。
- アプリ内の遷移リンク（ヘッダーのナビゲーション・ブランド・設定歯車、月切替、`LinkButton`／`ActionLink`、戻りリンク、取引行・振替行・残高行）は `PrefetchLink` を使います。画面内に入っただけでは先読みせず、マウスのホバー・キーボードのフォーカスで先読みします。本文ページへのタッチ・押下直前の先読みは遷移のRSC取得と重なり、計測では完了時間を短縮しなかったため行いません。カードなど通常の `Link` に任せるリンクはタッチ時にも先読みします。開いているページと同じURLは先読みしません。取引の絞り込みは `NavigationShell` を通さず `FilterTransition` で URL を置き換え、確定後に `syncCommitted` で外枠の現在地（月・検索条件）を合わせます。

`globals.css` はトークン、リセット、ベース文字組み、フォーカス表示、モーションの安全策だけを管理します。色トークンはライト（`:root`／`[data-theme='light']`）とダーク（`[data-theme='dark']`）で同じ名前を再定義し、影・スクリム・セレクトの矢印もトークンにします。CSS Module はテーマで分岐せず、色を直書きしません。概要、カテゴリ内訳、取引行、残高、フォーム、設定、取込、ナビゲーションのルールは、それぞれの CSS Module に置きます。共有部品は構造・状態を React に、見た目を部品専用 Module に分け、`:global` の大きなラッパーやクラス名対応表は作りません。
設定画面のデータ管理では、通常の設定行として `取り込む` を先に置き、破壊的な `すべてのデータを削除` は危険色の行として最後に置きます。リンクは画面遷移、button はフォーム送信や開閉・状態変更に使います。表示ラベル付きリンクには同じ文言を重複する `aria-label`/`title` として付けません。設定歯車のようなアイコンだけのリンクは `aria-label` と `title` を付けます。

| `--leading-body`    | `1.6`  | 本文、説明、複数行の補助文 |
| `--leading-meta`    | `1.45` | `h3`、日付などのメタ情報   |

ページ幅は wide `65rem`、narrow `42rem`、import `44rem` です。概要・取引・残高は同じ wide 幅と同じ左右余白を使い、画面を切り替えても本文の左端・右端・開始位置が動きません。ページ固有 Module でページ幅や `--space-page` などの余白トークンを上書きしません。日本語の本文・説明文は `--leading-body` を使い、大きな金額は `--leading-tight` を使います。ルートや本文のフォントサイズを px で固定せず、金額には `font-variant-numeric: tabular-nums` を使います。

## 金額の色

金額は `SignedYen`／`moneyTone`／`moneyToneClass` で符号または収支方向から色を決め、概要・残高・取引一覧・取込・振替で同じ規則を使います。正数・収入は青、負数・支出は赤、0円と振替は通常のインク色です。ダークでも意味は同じで、`--money-positive`／`--money-negative` の明度だけを上げます。資産・負債の集計はラベルの意味を優先し、純資産と資産行の残高は値の符号に従います。色だけに依存せず、`＋`／`−` とスクリーンリーダー用の符号も残します。

## 空状態

`EmptyState` は表示位置によって `page` と `section` の密度を使い分けます。残高の空状態は「表示する資産がありません」とし、説明と「資産を登録」リンクを同じ順序で持ちます。装飾を増やさず、既存の紙面・文字・罫線の表現を保ちます。

## 表示文字の間隔

画面が作る説明文・ラベルでは、日本語と ASCII の単語境界に半角スペースを一つ置きます（例: `Excel ファイル`、`5 MiB まで`）。カテゴリ名・メモ・資産名など利用者入力の保存値は、表示時にも書き換えません。

残高一覧は銀行・クレジットカードともに、資産名の右側を二列の金額領域として揃え、見出し行と各資産行で列幅・間隔・右端を共有します。銀行の「支払予定」は、設定完備カードのうち同じ銀行を引落口座に指定した全カードについて、当月に支払日を迎える締め済み未払い分の残額を合計します。該当カードがない銀行も 0 円を表示します。金額はフォントを縮めたり切り捨てたりせず、資産名と金額列が内容に応じて折り返し・再配置されます。

設定完備のクレジットカードは、「決済予定」列に請求確定（`billed-unpaid`／`overdue`）かつ未払いの全請求期間の残額、「未決済」列に現在の請求期間の締め前（`unbilled`）残額だけを表示します。設定なし・設定不備のカードは両列とも不明表示にします。過払いなどで現在負債が信用（負数）になった場合も符号と既存の信用側の色を保ちます。すべてのカード行は一つのクレジットカードグループに元の順序で並べ、別の見出し行には分けません。請求期間の詳細、専用フィルター、請求セクション、支払専用画面は追加せず、カード名から既存のカード別取引一覧へ移動します。

フォントはローカル配信の `@fontsource-variable/noto-sans-jp@5.3.1`（OFL-1.1）を使います。system-ui は OS ごとに Hiragino、Yu Gothic UI/Meiryo、Noto Sans CJK JP などへフォールバックして実フォントが変わるため、CSS ドメインの CDP `CSS.enable` と `CSS.getPlatformFontsForNode` で概要・フォームの日本語見出し、本文、金額、ボタン、入力を比較しました。Noto 版は可変フォントの既定インスタンス名として `Noto Sans JP Thin` を返しましたが、概要 1280px で 20 subset・448,756 bytes、フォーム 390px で約 449KB を転送し、実使用ウェイトは本文・入力 400、ボタン・見出し 500、金額入力 500 でした。`document.fonts.status` は loaded、観測 CLS は 0 です。unicode-range 分割で未使用文字を読み込まず、外部フォントサービスには依存しません。

動きの基本 easing は `cubic-bezier(.2,.7,.2,1)` です。ボタン・リンク・行の色と背景は 160ms、押下は 1px、本文の月・ページ切替は React `ViewTransition` の本文用 named transition で新しい内容を 200ms fade-in（古い内容は短く fade-out）、ヘッダー・ナビゲーションは遷移対象外として位置を保ちます。遷移先の骨組みを表示した遷移（ページ切替と月の切り替え）では、確定した本文が骨組みの位置へその場で入るよう fade を行いません。カテゴリバーは初回表示と月変更だけ 420ms（85%→100%、opacity .3→1）とします。カード・インポート確認・削除確認のスクリムは `--scrim` を 160ms（`--motion-fast`）でフェードインし、カード／ダイアログのパネルは `--motion-enter`（240ms）で下から 0.75rem（ダイアログは 0.5rem）持ち上げながら scale 0.985 から入れます。サーバーエラー用ダイアログの `::backdrop` は `--scrim-dialog` の静的なスクリムで、アニメーションしません。全画面の `backdrop-filter` は使いません。スクリムの濃度で背景を落とし、blur 合成による描画コストを避けます。カード表示中は `html[data-overlay-open]` が付き、本文の ViewTransition を止めて、リストのフェードとカードの出現が重ならないようにします。アニメーション中の要素は移動・拡大しているため、カード内の寸法を測る E2E は `waitForMotion` でアニメーションの完了を待ちます。`prefers-reduced-motion: reduce` では View Transition を即時化し、各所有 Module でも transform・bar scaling・animation を無効にします。
